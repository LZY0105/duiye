# 许可证变更：AGPL-3.0 → MIT

对页从上游 [strangelion/LaTeXSnipper_mobile](https://github.com/strangelion/LaTeXSnipper_mobile)
分出来时继承了它的 **GNU AGPL-3.0**。本文件记录从哪一版起改为 **MIT**、为什么
可以改、以及哪些东西**没有**跟着改。

## 分界

| | 许可证 |
|---|---|
| 这个提交**之前**的每一个版本 | GNU AGPL-3.0（原文见 [LICENSE.AGPL-3.0](../LICENSE.AGPL-3.0)） |
| 这个提交**起** | MIT（见 [LICENSE](../LICENSE)） |

**历史没有被改写，也不该被改写。** 那些版本确实包含上游受 AGPL 保护的代码，
它们就该是 AGPL 的；而 AGPL 本来就允许分发它们——条件是源码可得（仓库本身就
是）、许可与版权声明保留（历史提交里都在）、修改版以 AGPL 发布（那些提交里的
`LICENSE` 就是 AGPL）。

删掉历史反而是在掩盖来源。摊开说更站得住。

## 为什么分界点之后可以不是 AGPL

AGPL 第 5 条管的是「上游作品的修改版」。当一份代码里不再含有上游**受保护的
表达**时，它不是他的作品的修改版，第 5 条就够不着它。

这个判断基于逐行测量，方法、结果和判据都在
[docs/上游代码清理.md](上游代码清理.md)，数字用 `npm run check:upstream` 现算，
不抄在文档里。摘要：

- `src/` 下 90 个模块，分叉点就存在的只有 14 个，且全是外围（日志、多语言、
  设置页、下拉选择器、背景动效、更新检查）
- 这个软件的核心——两栏工作区、矢量笔迹层、无限草稿纸、对题引擎——在上游
  **没有对应物**，那些文件当时一个都不存在
- 仍逐字来自上游的行数约占手写代码的 1.3%，且全部落在语言骨架（`}`）、
  短语词条（`"设置"`）、API 表面（`import` 语句）、CSS 选择器名与属性声明
  这几类上

**这是一个判断，不是一条定理。** 它由技术测量支撑，但最终是法律问题。

## 没有跟着改的

**上游的版权声明**保留在 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
出处是事实，和许可证是两回事——即使不再有法律义务，把来处说清楚也该做。

**`LICENSE.AGPL-3.0`** 保留在仓库里。它不是历史遗留文件，是分界点之前那些版本
现在仍然适用的许可证。

**依赖的许可证**各自照旧。`npm run check:licenses` 守着这条线：在 AGPL 时代它
挡的是「不相容的依赖混进来」；改成 MIT 之后方向反了——MIT 作品里不能并入
GPL/AGPL 代码，那个脚本的判据也跟着换了。

## Agent 那部分：他的著作权，他已同意

**Agent 那部分代码的著作权属于 @allnothing571**，不属于本仓库所有者：

| 文件 | 行数 |
|---|---:|
| `native/agent-proxy/src/main.cpp` | 228 |
| `src/pdf/agent-panel.js` | 145 |
| `src/agent/agent-client.js` | 49 |
| `native/agent-proxy/CMakeLists.txt` | 43 |

共 8 个提交（`git log --author=WangJiyi`）。

这条命令里的 `WangJiyi` 是他 **git 配置里的作者名**，不是 GitHub 账号，两者不
一样：他的账号是 [@allnothing571](https://github.com/allnothing571)。分辨的依据
是他那两条 `Merge pull request` 提交——在 GitHub 网页上合 PR 才会留下那种签名，
作者被写成账号名。`github.com/WangJiyi` 是另一个不相干的人，早年的文档曾照他的
git 名字猜过去，链错了。

把这些代码以 MIT 重新发布需要他同意，而**他已经同意了**（2026-09-13 由仓库所有者
转述）。仓库随后公开发布。

这份记录里只写得出这一句：同意的**形式和原件**（邮件、聊天记录、issue 回复）不在
本仓库里，本文件也不替它作证。真要有人来问，能拿出原件的是仓库所有者，不是这份
文档。

**同意的是重新许可，不是转让著作权。** 那 465 行的著作权仍然是他的——MIT 也要求
保留版权声明，所以下面这些署名都不能省：README 里那一行、应用内「关于」块、以及
git 历史里他的作者身份（这也是不重写历史的另一个理由）。
