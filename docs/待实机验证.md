## 12. 记笔记：本子在平板上是不是也能写

新加的功能。**在桌面浏览器里已经端到端走通了** —— 新建、翻页、加页、写字、关掉重
开、换纸、封面、会话恢复，逐条验过；下面只列**平板上才可能不一样**的那几条。

设计上笔记本是一份**文档**（`src/note/note-document.js` 把自己装成 pdf-document 的
形状），所以它走的是 PdfPane 那一整套。也因此它出问题的方式和书一样，而不是另一种。

### 12a. 笔尖写上去跟不跟手

浏览器里是鼠标/合成事件，平板上是 Apple Pencil。笔迹层和书完全共用，所以理论上和
在书上写一样 —— 但纸是现画的（每次换缩放重画一张），值得看一眼有没有多余的重绘。

**怎么做**：新建一本横线笔记本，写满一页，放大缩小几次。

**期望**：和在 PDF 上写一样跟手；缩放时纸和字一起动，不错位。

### 12b. 加页之后缩放不变

加一页会把整份文档重新打开（页数变了就是文档变了）。浏览器里第一版写错过：自己拼
了个 `{pageNumber, zoom}` 传进去，缩放从 100% 跳到 316%。改成整份 `pane.state` 带
过去之后对了，但平板的 dpr 是 1.5，值得再看一眼。

**怎么做**：翻到最后一页，按工具栏上的「+页」。

**期望**：跳到新的最后一页，缩放百分比**不变**。

### 12c. 两栏一边书一边本子

这是这个功能最想要的用法：左边习题册，右边自己的笔记。

**怎么做**：左栏开一本 PDF，右栏开一本笔记本，拖分隔条改比例。

**期望**：两边各自适应宽度，笔记本这边不跳（分隔条那个 bug 在 `efc5606` 修的，
笔记本走同一条路，所以应该一样稳）。

### 12d. 纸张样式在平板上看得清

八种格子和四种纸色是和草稿纸共用的，但草稿纸是无限画布、本子是固定 A4 页 —— 同一
个「间距标准」在两者上看着大小不同。

**怎么做**：换几种格子和纸色看看。

**期望**：田字格、米字格在一页 A4 上大小合用；淡青、暖米在平板屏幕上看得出区别。

### 12e. 缩略图上有没有字

「找页面」里本子的缩略图要带上写过的笔迹。这一条在浏览器里没验（缩略图要开面板）。

**怎么做**：在两三页上各写几笔 → 打开「找页面」。

**期望**：写过的那几页缩略图上看得见笔迹，没写过的是空白纸。

## 11. Worker 渲染：装上新包之后走一遍真实的读书动作

PDF 的光栅化搬进了 worker（`src/pdf/pdf-render-worker.js`），并且 worker 里留住最
近 3 个页对象不 cleanup。**代码路径本身已经在这台平板上验过了** —— 用 CDP 把构建
产物注进去跑生产协议，结果记在下面；这一条要验的是「装成 APK、走真实 UI」时还对
不对。

已经验过的（2026-09-13，用注入的方式跑 `dist/assets/pdf-render-worker-*.js` 本体）：

| | 每次重渲 | 合计 | 主线程帧间隔 p95 | 最坏 |
|---|---|---|---|---|
| 原来：主线程 | 488–544ms | 3111ms | 14ms | 97ms |
| 现在：worker | 首次 602ms，之后 1–3ms | 610ms | 9ms | 10ms |

输出逐像素一致（同页同缩放，深色像素占比两边都是 0.03956）。478 页的书打开耗时
54ms。位图上屏 0–0.2ms。

### 11a. 真的走的是 worker，不是悄悄回退了

回退是静默的（功能不少，只是卡回去），所以必须显式确认。

**怎么做**：连上 CDP，开一本书，看 console。

**期望**：**没有** `[PDF] worker 渲染不可用，回退主线程` 这一行。有的话把 cause
抄下来 —— 那是这一整轮唯一的失败模式。

### 11b. 放大缩小

**怎么做**：开一本扫描版教材，连按五次放大、等落地，再连按五次缩小。

**期望**：第一次进一页仍然要等半秒（那是解图，没变），之后每换一档缩放应该几乎
立刻出清晰图。第 8 条那个「p95 72ms、最坏 191ms」的卡顿应该没有了。

### 11c. 缩略图上的批注还在

worker 默认给的是零拷贝的 bitmaprenderer 画布，那种画布拿不到 2d 上下文。找页面
板靠 `drawable: true` 拿一张能画的，漏了就是**缩略图有页面、没有批注**，不报错。

**怎么做**：在一页写几笔 → 打开「找页面」→ 看缩略图。

**期望**：缩略图上能看见刚写的那几笔。

### 11d. 书架封面

封面走的是零拷贝那条路（只 `toBlob`，不需要 2d 上下文）。

**怎么做**：文档库 / 书架看一眼。

**期望**：每本书都有封面图，不是灰块。

### 11e. 对题还对得上

抽文本现在在 worker 里跑。归行实现是和主线程共用的同一份（`pdf-extract.js`），但
cmaps 走的是 worker 自己拼的绝对路径 —— 拼错了不会报错，只会让中文变成一串看着
像模像样的乱码，然后匹配引擎照单全收。

**怎么做**：导入一本**有文字层**的练习册和答案册，跑一次对题。

**期望**：抽出来的是中文，不是别的文字系统的字符；匹配结果和以前一致。

### 11f. 内存

留 3 个页对象要占地方。注入测量时每页的边际开销在噪声以下（留 1/4/8 页分别是
387/387/374MB，全放了也是 374MB），但那是注入环境，不是真实使用。

**怎么做**：两栏各开一本书，翻二三十页，`adb shell dumpsys meminfo`。

**期望**：和以前同一量级（第 8 条记的是 325–364MB）。明显更高就把
`PAGE_HOLD` 调小。

## 1. 原生代理层：同步失败时那条 Promise 落不落地 · `292d6a5`

**为什么只能真机验**：原生层可以在 `submit` 还没返回时就把事件发出来，而

模拟不出真实的那一拍。

**怎么做**：连上之后在 DevTools 里跑

```js
const api = Capacitor.Plugins.NativeProxy;
const t0 = performance.now();
api.addListener('proxyEvent', e => console.log('回音', Math.round(performance.now() - t0), e));
api.submit({ service: 'ocr', op: 'recognize', payload: {} });
```

**期望**：`UNIMPLEMENTED` 在几十毫秒内回来。用 `src/native/native-proxy.js` 的
`recognize()` 再走一遍，`await` 能落地、不悬着。

**已经验过的**：桥本身通（`loaded: true`、两个空位 `ready:false`、错误码原路回到
JS）——那是平板还在时做的。

## 2. 发布版里代理层还在不在 · `292d6a5`

**为什么只能真机验**：R8 的映射表证明了 `onNativeEvent` 名字保住了，但没证明
`System.loadLibrary` 在真机上成功、`JNI_OnLoad` 拿到了方法。debug 构建不混淆，
所以这件事只在发布版里可能发作，而且发作起来是安静的：类名保住了（`native
<methods>` 那条规则顺带保的），看起来像「库装上了却不动」。

**这一条会抹掉平板上的数据。** 发布版和现在装着的 debug 包签名不同，Android 不
允许换签名覆盖安装，必须先卸载——而卸载会连数据目录一起删。完整流程见下面
「验完再换回来」那一段。

**动手之前：发布版得先有把密钥。**

没有 `android/app/keystore.properties` 时 `canSign` 为假，`assembleRelease` 会
跳过签名，产出的是 `app-release-unsigned.apk`——装不上去。

这里有个选择值得先想：**要不要现在就生成正式密钥**。

- 生成正式的：以后公开发版用同一把，等于「验的就是将来发的」。代价是这把密钥
  从此不能丢——丢了现有用户永远收不到更新，只能换 appId 重来。
- 生成一次性的：只为这次验证，验完删掉。发版时再另生成。

不管哪种，命令一样（在 `android/app/` 下）：

```bash
keytool -genkeypair -v -keystore release.keystore \
  -storepass '<口令>' -alias duiye -keypass '<口令>' \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=duiye,O=duiye,C=CN"

printf 'storeFile=release.keystore\nstorePassword=%s\nkeyAlias=duiye\nkeyPassword=%s\n' \
  '<口令>' '<口令>' > keystore.properties
```

两个文件都被 `.gitignore` 拦着（`*.keystore` 和 `keystore*`），不会进仓库。
**正式密钥要另外备份到这块硬盘之外。**

> 回收，但留着会让人以为新旧混了。

把结果写进日志缓冲区。所以在平板上直接看：

> 设定 → 开发者选项 → 开发者模式 → 查看日志

**期望**：日志里有 `[PROXY] 原生层已加载（agent=…，match=…，ocr=…）`，
三个位置都写着 `no implementation registered`——那是现在正确的状态。

> `match` 这一位和另外两位不同：答案匹配**现在就有实现**，在 JS 那边跑。
> 这个空位是留给以后把计算搬到 C++ 的，见 `src/pdf/native-matcher.js`。
> 所以它 `ready:false` 不代表对题功能不可用。

出现 `原生层不在：浏览器里跑，或者库没能加载`，就是 R8 把 `onNativeEvent` 改名了
——去看 `adb logcat | grep -iE "duiye_proxy|UnsatisfiedLink"`，并检查
`proguard-rules.pro` 里那条 `-keep class io.github.lzy0105.duiye.proxy.NativeProxy`
还在不在。

**同时看一眼 logcat**（这一条不依赖应用自己的日志）：

```bash
adb logcat -d | grep -iE "duiye_proxy|UnsatisfiedLink"
```

**期望**：有一行 `nativeloader: Load ...libduiye_proxy.so...: ok`，
没有任何 `UnsatisfiedLinkError`。

> **这一层现在没有任何实现。** 三个位置（`agent`、`ocr`、`match`）都还空着，
> 除了开机那次探测，应用里零调用。验它仍然有意义（它是以后接 OCR、以及把答案
> 匹配搬到 C++ 的那条路），但它今天不影响任何功能。
> 平板上真正在用的 Agent 走的是另一套：`agent-client.js` → `127.0.0.1:8787` →

> 没人在听，Agent 面板一按就是「无法连接本地 Agent 代理」。

## 9. A09：同一页开在两栏 · ✅ 2026-09-12 验过

**先挖出来的一件事**：A09 说的「同一份 PDF 同时开在两栏」，这个程序原来**根本做不
到**。书架里点一本已经开着的书，`chooseSlotFor` 直接把人带回它已经在的那一栏，不
问也不给第二份，理由写的是「一栏里放不下两份」。那条理由只对同一栏成立（一栏里
两项同一份文件会抢同一个阅读位置），两栏各有各的 entry、各记各的页码，互不相干。
所以先放开了这条限制（`_destinationSpec`），A09 才有得验——顺带这也是这本书最该
被这么用的时候：478 页的习题册，题在前面答案在后面，同一本对照着看。

**怎么验的**：两栏都开 `陈现平300例第二版` 第 31 页，直接读 IndexedDB 里
`pageInk` 那条记录的 `strokes.length`，不看画面猜。

| 量到的 | 数 |
|---|---|
| 起始 | 2 笔 |
| a 栏落一笔，120ms 后看 b 栏画布 | **变了**（此时库里还是 2 笔——重画没等那 400ms 的落盘）|
| a 落盘后 | 3 笔 |
| b 栏再落一笔，看 a 栏画布 | **变了** |
| b 落盘后 | **4 笔** |

最后那个 4 是整件事的分水岭。老的实现在这里是 3：b 栏手里是当初那份 2 笔的副本，
加自己那一笔写成 3，把 a 刚画的那一笔整个盖掉——人看到的是「我刚画的没了」，还是
在另一栏里没的。

**撤销**：各撤各的。b 栏撤 → 3，a 栏撤 → 2，回到原样，谁也没撤掉对方的。

**擦除**：a 栏画一条（3 笔），b 栏用橡皮沿同一条线擦过去 → a 栏画布立刻变，库里
回到 2 笔。

**重启之后照样**：`force-stop` 再起来，两栏仍是同一本同一页，整套数重跑一遍
（2 → 3 → 4），说明会话恢复那条路也照样过登记处。

**句柄**：不存在提前销毁。每一栏各自 `openStoredDocument`（`pdf-library.js:169`
每次都重新 `openPdfDocument`），一栏关掉不碰另一栏。代价是同一本书的字节和
pdf.js 的那份状态在内存里有两份。

**还留着的两处小的**（都不丢数据，没修）：

- **书签的 ☆ 不跨栏刷新**：两栏都停在第 7 页，一栏加了书签，另一栏那颗 ☆ 要等它
  自己换页才变实心。和笔迹是同一类问题（一份共用的东西、两个视图），但书签存的是
  一条一条的记录，不是整层盲写，所以只是看着旧，不会丢。
- **撤销把笔迹放回原位时用的是下标**：`InkLayer.restore` 按 `removeByIds` 记下的
  下标插回去。另一栏在这中间加了笔，下标会偏一点——只影响前后压盖的次序，笔一根
  不少。

### 追加（同日）

第 7 条验完之后发现它**动得太勤**：那条菜单栏是居中的一颗胶囊，真机上量到横跨
360–840，而工具栏靠在最左边的 10–63——两者横向根本不相交，可安全区是按整条底边
算的，于是菜单栏一升起来工具栏就被顶上去还缩短一截，而它从头到尾没被挡住过一个
像素。现在按横向是否相交来判（不能按纵向：顶上去之后纵向就不相交了，会来回摆）。
改完再拖：工具栏全程 `10,148,53,572` 纹丝不动。

**还没在真机上验的那一半**：工具栏真的横在菜单栏上方时（贴底边、或者拖到屏幕中
间那一段）该被顶起来。单元测试里量了（压住 → 78px，擦边 → 0），真机没验，因为
那要挪动你的工具栏位置。

### 顺带记下的

- **驱动这台机器的坑**：合成 `PointerEvent` 没有真实指针，`setPointerCapture` 会抛
  `NotFoundError`，把 app 的 pointerdown 处理函数从中间打断——症状是「事件到了画布
  却什么都不发生」。驱动前先把 `Element.prototype.setPointerCapture` 垫成空函数。
- **旋转手柄和动作条挨得很近**：手柄圆圈落在套索线右下角，条就在线下方 12px——两者
  在屏幕上几乎贴着。真人用笔时会不会误触，还得你自己试。
