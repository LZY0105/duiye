# 上游代码清理：做了什么，剩下什么，为什么停在这里

这份文件记录对页从
[strangelion/LaTeXSnipper_mobile](https://github.com/strangelion/LaTeXSnipper_mobile)
分出来之后，清理上游代码的方法、结果，以及**哪些没有清、为什么不清**。

写下来是因为最后一条最容易被误解。一份只报「还剩 N 行」的材料会让人以为目标是
把 N 追到零；而把 `}` 和 `"设置"` 也追到零，代码和界面都会变差，法律上什么都不
改变。

数字不抄在这里，用脚本现算：

```bash
npm run check:upstream
```

---

## 这个软件和上游的关系

上游是一个**公式识别（OCR）应用**：拍照或截图，识别出 LaTeX，编辑、导出。

对页是一个**教材批注应用**：两栏并排开 PDF，用笔在上面写字，在练习册和答案册
之间自动对题。识别功能已经整套删除。

这个关系在代码里是可以量的。`src/` 下现在 90 个模块：

| | 模块数 | 行数 |
|---|---:|---:|
| 分叉点（`8c70c28`）就存在的 | 14 | 3,650 |
| 分叉之后新建的 | 76 | 29,433 |

分叉之后新建的那 76 个里，包含这个软件的全部核心：

- `src/pdf/` 16,821 行 —— 两栏工作区、队列、书架、对题引擎
- `src/ink/` 4,643 行 —— 矢量笔迹层，以及同一页开在两栏时的共享机制
- `src/scratch/` 1,770 行 —— 无限草稿纸

分叉点就存在的那 14 个是外围：日志、多语言、设置页、下拉选择器、背景动效、
更新检查、`base.css`、`mobile.css`、入口与引导。它们全部被重写过一轮以上。

## 测量方法

`scripts/upstream-survival.mjs`，一条命令重跑。

**判定口径**：一行「还是上游的」＝ 去掉首尾空白之后，它在**同一个文件**的上游
版本里原样出现过。

- **不用 `git blame`。** blame 回答的是「谁最后碰过这一行」——改个缩进就算你的
  了。著作权关心的是原文还在不在，不是谁最后碰过。
- **不用 LCS（最长公共子序列）。** LCS 考虑顺序，得出的数更小。这里故意用更宽松
  的「出现过就算」：**往多了报，不往少了报**。一份用来说明「剩得很少」的材料，
  宁可把自己说得更不利一点。

### 三类不计入

**许可证原文**（`LICENSE`）。必须留着 —— 删掉它才是侵权。

**工具生成的**。`package-lock.json` 是 `npm install` 解出来的依赖树，
`android/gradlew` 是 `gradle wrapper` 生成的。换谁跑都是这些字节。

**Capacitor 的 Android 模板**。这一类最容易算错，值得单独说：

> `npx cap add android` 会从 `@capacitor/cli/assets/android-template.tar.gz` 解出
> 一整套 gradle 与 manifest。上游跑过这条命令，本仓库也跑过，两边当然逐字相同
> —— 但那不是上游的表达，是 Capacitor 的模板。
>
> 早期的统计没有区分这一点，把它们全算成了上游的。把模板解出来当第三方逐行比对
> 之后：算在「上游写的」名下的 180 余行里，约 145 行属于模板。
> `android/build.gradle`、`variables.gradle`、`gradle.properties`、
> `settings.gradle` 是 100% 模板。
>
> 脚本现在会自己解开那个 tarball 来扣除。

## 清理做了什么

按提交顺序，每一条都能在 `git log` 里查到：

| | 做了什么 |
|---|---|
| 脱钩 ① | 删掉 `assets/` 4.3 MB 死重和一并复活的上游 logo |
| 脱钩 ② | 启动图与启动屏换成对页自己的；Android 12+ 的启动屏也钉住颜色 |
| 脱钩 ③ | 语言包 1115 条上游词条降到 59 条；`ocr.css` 整个删除；`base.css` 上游样式 249 → 19 条规则；五个 JS 模块 101 → 63 行；`index.html`；`mobile.css`；CI、文档、构建配置 |
| 脱钩 ④ | 包名 `com.latexsnipper.app` → `io.github.lzy0105.duiye` |
| 脱钩 ⑤ | 删掉 iOS 构建那一套（260 行，与上游逐字节相同且在本工程里跑不起来） |
| 脱钩 ⑥ | 重写两个 CI 工作流 |
| 脱钩 ⑦ | `sw.js`、`.gitignore`、签名配置 |

清理的同时修掉的真实故障（重写的副产品，也是重写值得做的原因）：

- `exportAsZip` 调用了从未加载的 JSZip
- 「检查更新」查的是上游仓库的发布
- 下拉菜单的选项文字只在初始化时抄一份，语言一换就停在旧语言上
- Service Worker 预缓存表 17 项里 13 项指向不存在的文件，每次安装静默失败
- Service Worker 把 404 和 500 也存进缓存，于是一次偶然的失败变成永久的失败
- CI 用 `sed` 把算好的 `versionCode` 覆盖成小两个数量级的值，CI 出的包装不到本地装过的机器上
- 安全扫描的 ESLint 与 gitleaks 两步都挂着 `|| true`，永远不会失败
- 「i18n 合规」检查按每个中文字符打印一行警告，每次输出两万余行
- 会打进 APK 的依赖里有一个 critical（`tar` ≤7.5.20）

## 剩下的，和为什么不清

脚本把剩余分成六档。前五档是**形式由语言、框架或既有结构定死的**：

**语言骨架** —— `}`、`export default {`、`</div>`、`<!DOCTYPE html>`。
一行只有标点。

**短语与词条** —— `"nav.settings": "设置"`、`"settings.about": "关于"`。
单词和短语不构成受保护的表达；而且「设置」就是这个功能的中文名，换掉只会让界面
用词变差。

**API 表面** —— `import { t } from './core/i18n.js';`（由文件布局定死）、
`export function initSettings() {`（由调用方定死）、
`- uses: actions/checkout@v4`（GitHub Actions 的固定写法）、
`navigator.serviceWorker.register('/sw.js')`（MDN 上的标准写法）。都只有一种写法。

**选择器（类名）** —— `.bottom-nav {`、`.splash {`、`.settings-tab {`。类名由
HTML 结构定下来；要改就得连 HTML 和 JS 一起改三十来处，而类名是短语。纯粹的换皮，
只增加回归风险。

**声明（属性: 值）** —— `position: fixed; inset: 0;`、
`--safe-b: env(safe-area-inset-bottom, 0px)`、
`*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }`。
最后这条通用重置几乎出现在每一个 CSS 工程里。

**其余** —— 只有这一档需要人一行一行看。正则判不了「这算不算表达」，所以那一档
只负责把范围缩到能人工过一遍的大小，不负责下结论。

```bash
npm run check:upstream -- --list    # 把这一档逐行摊开
```

### 这一档人工过了一遍，结论

逐行看下来，这一档里绝大多数仍然不是表达：

- `index.html` 是最大的一块，内容是 HTML 样板（`<html lang="zh-CN">`、
  `<meta charset="UTF-8">`）加上**设置页的 DOM 结构**：`分组 > 小节 > 标题 + 控件`。
  那是最常规的设置页排法——iOS 设置、Android 设置、几乎每个应用都这样。
- `settings.js` 是 `document.getElementById('setSkinSelect')` 这一类，由 HTML 里的
  元素 id 定死；以及 `addEventListener('change', ...)`，只有一种写法。
- CI 工作流里剩的是 GitHub Actions 的 schema 关键字（`on:`、`jobs:`、`steps:`、
  `with:`）和 `${{ secrets.X }}`。

一度考虑把设置页整个重写，因为它那套 id 与类名（`setSkinSelect`、`set-group`、
`set-toggle-track`）确实是从上游继承的。**没有做**——那和「把类名换一遍」是同一
件事，只是范围更大、回归风险更高，而法律上什么都不改变。对设置页开这个例外，
等于承认前面那条原则只是说说。

### 非字面的那一半

以上量的都是字面。结构上的承袭（模块划分、组织方式）不会出现在任何行计数里，
而那才是净室重写最常翻车的地方。

这个项目在这一点上的事实前面已经列过：`src/` 下 90 个模块，分叉点就存在的只有
14 个，且全是外围；两栏工作区、笔迹层、草稿纸、对题引擎——这个软件的全部核心——
在上游**没有对应物**，那些文件当时一个都不存在。

留下的结构性承袭是那 14 个外围模块的 API 形状：日志模块有 info/warn/error 和一个
导出方法，多语言模块有 t()/setLang()/onLangChange()。这些形状本身是这类模块的
通行做法。

### 一条原则

**净室重写的目标是零受保护的表达，不是字面的零。**

把 `initSettings` 改个名字纯粹为了让匹配断掉，代码会变差，而法律上什么都不改变
—— 这正是让净室变成表演的那种做法。真正减少风险的是重写有实质内容的逻辑，
而那一部分已经做完了。

## 还没做的

**新仓库。** 工作树清干净了，`git log` 里还有上游的代码 —— 分发这个仓库就是在
分发它。要真正脱开，最后一步是建一个不带上游历史的新仓库。

**顺序不能反：先把表达清到零，再动 `LICENSE` 和出处声明。** 反过来做 ——
先摘许可证声明再慢慢重写 —— 那段时间里每一次分发都是无许可的。

## 现在的许可状态

**这份清理的结论被用掉了**：许可证已由 AGPL-3.0 改为 **MIT**。分界点、判据、
哪些东西没跟着改，记在 [docs/许可证变更.md](许可证变更.md)。

分界之前的每一个版本仍然适用 AGPL-3.0，原文保留在
[LICENSE.AGPL-3.0](../LICENSE.AGPL-3.0)，历史没有被改写 —— 那些版本确实含有
上游的代码，它们就该是 AGPL 的。

上游的出处声明留在 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
出处是事实，和许可证是两回事：即使不再有法律义务，把来处说清楚也该做。

`scripts/check-licenses.mjs`（`npm run check:licenses`）守着另一头，而它的方向
**跟着反过来了**：

| | 要挡的是 |
|---|---|
| AGPL 时代 | 比 AGPL 还严或条款冲突的（GPL-2.0-only、SSPL、BUSL） |
| MIT 时代 | **所有 copyleft**（GPL / AGPL / LGPL）—— 并进来一个，整份作品就得跟着它走，而 LICENSE 写的是 MIT |

**还没办的一件事**：Agent 那部分（`agent-panel.js`、`agent-client.js`、
`native/agent-proxy/`，共 465 行）著作权属于 @allnothing571。以 MIT 重新发布这些代码
**需要他同意**，在拿到之前这个仓库不应公开。

本文件是事实记录与技术分析，不是法律意见。
