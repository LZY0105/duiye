# 对页 

[简体中文](README.md) | [English](README.en.md)

**教材手写批注与对题** — 一款面向 Android 平板的手写做题应用：把练习册和答案册同屏打开，用触控笔在 PDF 上直接批注，并为当前页的题目自动找到对应答案。

全部处理都在设备内完成，不上传任何文档。

## 关于名字与图标

名字取「对」与「页」两层意思：**对答案**，以及**对开的两页**。产品做的正是这一件事——左边一页题，右边一页答案，由引擎判断哪一条对应哪一题。

图标是同一个想法的几何写法：两页并排，左页缺一个口，右页凸出正好补上，在中线互相咬合。缺口与凸起半径相同、圆心都落在 x=256，所以缩到 24px 仍然读得出「两页彼此相合」。这既是匹配引擎，也是用户真正会去拖动的那条分隔条。图标里没有铅笔、公式或学士帽——那些描述的是学科，不是工具。

## 项目来源（Provenance）

本仓库由两个独立的上游合并而成。两个来源都在下面写明，便于核对与追溯。

### 1. 应用主体（base）

应用主体来自 **LaTeXSnipper Mobile**：

> **https://github.com/strangelion/LaTeXSnipper_mobile**

上游是一款本地 OCR 与公式编辑应用，提供了 Capacitor/Android 封装、PDF 渲染、设置与国际化等基础能力。本仓库最初从它分出。

此后核心部分整体重写，上游的代码已不在其中，许可证也随之由 AGPL-3.0 改为 **MIT**。分界点、判据与仍然保留的出处声明，记在 [docs/许可证变更.md](docs/许可证变更.md)。

### 2. 答案匹配引擎（matching engine）

同屏对题所使用的匹配引擎来自一个独立仓库：

> **https://github.com/LZY0105/Math-answer-to-question-matching-model**

**本软件使用该引擎。** `src/pdf/` 下的 21 个模块直接来自该仓库，与其 `main` 分支保持一致，引擎自带的回归测试也一并移植到了 `test/`。

引擎解决的问题是：两本 PDF 除了印刷内容之外没有任何共同标识符时，判断答案册里的哪一条对应练习册里的哪一题——或者拒绝作答。它按“最便宜的信号优先”分级：书签层级题号 → 目录对齐 → 数学加权相似度 → 有界序列对齐，并且**在两本书未被确认为配套之前不会给出自动答案**。

引擎以 **MIT** 许可证发布（© 2026 LZY0105），与本仓库一致。

## 这个版本做了什么取舍

上游是一款 OCR 应用。本版本把它**精简为手写做题工具**：识别、公式编辑器、模型管理、AI 服务商、识别历史全部移除，只保留“课本”这一条主线及其必需的设置。

被移除的功能连同其代码完整保留在本地分支，未来需要时可以取回：

| 分支 | 内容 |
|---|---|
| `feature/with-ocr-preserved` | 精简前的完整版本（含 OCR、编辑器、模型与 AI 服务商） |
| `feature/ocr-and-editor-preserved` | 更早的完整版本 |

围绕识别栈的周边设施也一并清掉了：模型打包脚本 `scripts/package-models.js` 与调用它的 `package-models.yml`、ONNX 量化脚本 `scripts/quantize.py`、七个 Python 模型测试与它们共用的 `test_utils.py`，以及运行这些测试的 `test/run_tests.sh`。它们全部来自上游，而识别功能删掉之后，它们指向的东西一个都不在了：打包脚本读的 `public/models/` 目录不存在，量化脚本里写死的是另一台机器上的绝对路径，`run_tests.sh` 点名 22 个测试文件、其中 8 个在这次清理之前就已经不在仓库里。测试的唯一入口是 `npm test`。

上游留下的代码也在逐步换掉。整份工程约五万五千行手写代码里，还逐字保留着上游原文的是 **约 700 行、1.3%**——不含 `LICENSE`，也不含 Gradle wrapper、Capacitor 模板、`package-lock.json` 这些换谁跑都一样的生成物。这个数不抄在文档里，`npm run check:upstream` 现算。`src/core/logger.js`、`i18n.js`、`update-checker.js`、下拉选择器与背景动效都已重写，`status.js`、`splash.js`、`constants.js` 因为无人调用而直接删除，iOS 构建那一套（两个脚本加两份 `ExportOptions.plist`）因为在这个工程里从来就跑不起来而整套移除。

重写最初不是为了摆脱许可证，而是因为逐个读过去之后，其中好几处本来就是坏的（清到后来上游的表达确实归零了，许可证也随之改为 MIT，见 [docs/许可证变更.md](docs/许可证变更.md)）：`exportAsZip` 调用了从未加载的 JSZip，「检查更新」查的是上游仓库的发布，下拉菜单的选项文字只在初始化时抄一份、语言一换就停在旧语言上，CI 里那一步用 `sed` 把算好的 `versionCode` 覆盖成一个小两个数量级的值、于是 CI 出的包装不到本地装过的机器上。

**移除 OCR 不影响对题。** 匹配引擎从 PDF 书签树解析题号，只有在题号对不上时才退回文本相似度。在四本真实考研教材上，全程没有任何识别器参与，仍然做到 **508/508 全部解析、零错误、HIGH 置信度 100% 精确率**。

唯一受影响的情形是**既没有书签、文字层也不可读的纯扫描件**——这种文档会明确报告“需要 OCR 后才能匹配”，而不会猜测。

## 核心功能

- **每栏一队内容**：一栏不再只装一份文件。新开的文件或草稿纸插在当前项之前，被它换下来的那一份转到下层——不是关闭，随时可以唤回。切换行上滑取下一项、下滑取上一项；点标题打开本栏内容列表直接选，点选不重排。两栏各自独立循环。
- **同一本书可以同时开在两栏**：题在前面、答案在后面的习题册，不用再来回翻。两栏各记各的页码与缩放，而笔迹是同一份——哪边落笔或擦掉，另一边立刻跟着变。
- **无限草稿纸**：四个方向没有边界，负坐标就是普通坐标，缩放 25%–400%。草稿纸铺满整栏——没有内缩的纸卡、没有投影、没有固定长宽比；单张还可以进入专注模式占满整个工作区。八种底纹（空白 / 点阵 / 方格 / 横线 / 坐标格 / 等距斜格 / 田字格 / 米字格）、四种纸色、间距与导线浓淡可选。样式属于草稿纸本身，跟着它换栏、重启都不变，且从不改动笔迹。
- **笔记本**：和草稿纸是同一个「新建纸张」里的两个模式，纸张样式共用同一套（八种底纹、四种纸色）。差别只有一条，而那一条决定了别的全部：草稿纸是一张没有边界的纸，笔记本是**一叠有边界的纸**——像课本一样一页一页翻，新建时定页数，写满了在工具栏上加页（只能往末尾加：往中间插会把后面每一页的页码整体推后，而笔迹是按页码存的）。
  实现上它不是「能翻页的草稿纸」，而是**一份文档**：`note-document.js` 把自己装成和 PDF 相同的形状（几页、第 N 页多大、长什么样、有什么字），于是翻页、缩放、适合宽度、位图缓存、预取、笔迹对齐、缩略图、书签、封面、会话恢复整套东西一行都不用改。页面是现画的不是存的——一千页的空本子在库里也只有几十个字节。
- **跨栏移动**：任何一项都可以放到另一栏的任意位置。整理内容面板里两栏并排，拖手柄或点「移动到…」走的是同一次原子提交——两个队列要么一起变，要么都不变。
- **导入时列出本机所有 PDF**：顶上那一排的「导入」点开是一张单子（导入练习册 / 导入答案册），
  选完弹出的不是系统选择器，而是应用自己的面板——**全机的 PDF 一次列出来**，按时间排好，
  想找就搜名字。系统选择器的问题不是难看，是要人一层层翻目录，而人记得的是「那本谢惠民」，
  不是它在哪个文件夹。
  「只看得见 PDF」在这里是结构上成立的，不是一个可以被绕过的筛选条件：数据源本身就只有
  PDF（查 MediaStore 时按 MIME 过滤，而不是按文件名后缀——一份没有 .pdf 后缀的 PDF 照样
  是 PDF）。点开头的目录会滤掉，那里面是文件管理器的缓存副本和解压残留，不滤的话同一本书
  会用两个名字出现两次。
  **这需要「所有文件访问权限」**：从 Android 11 起，PDF 在 MediaStore 眼里不是媒体文件，
  没有这个权限的应用只看得见自己创建的那些——别的应用下载的、微信存的，一个都看不到。它没
  有应用内弹窗，只能把人送到系统设置里自己打开。所以**没权限时先弹窗问，再说别的**：点
  导入那一刻就说清楚要哪个权限、为什么要、以及它只能在系统设置里开，按下去真的跳到本应
  用那一页，回到前台自己再看一眼，给了就直接开面板。原来的顺序是反的——先把面板摊开，
  再在空面板里放一行「需要权限」，那等于先把人领进一间空屋子再告诉他门没开，而一张空面
  板看着更像「这台机器上一份 PDF 都没有」。
  那张单子上一直有「这次用系统选择器选一份」。这个权限听起来很大，它也确实很大，拒绝它
  是合理的选择；拒绝之后照样导得进东西，这条退路才是这个设计成立的前提。插件里没有任
  何删除或修改文件的方法，它唯一会写的是导出：只在「文档/对页」里新建文件（见下面的
  「导出 PDF」）。
- **书架式文档库**：按封面认书，不按文件名查表；点开时那本书自己翻开到目标栏。第一格永远是使用说明，装完软件就在，跟着界面语言走。
- **文件夹**：书多了就分一分——一本书右上角的 ⋯ →「移动到文件夹…」，还没有文件夹就在那张单子里当场建一个。点开文件夹只看见里面的东西，外面那些书不再摆在架子上：「分类」的全部意义就是屏幕上少几样东西，分完类还是全都在，人只会觉得这个按钮没反应。文件夹是个格子，不是个箱子——删掉文件夹，里面的书一本不少地回到外面；同一份东西同时只在一个文件夹里。站在文件夹里导入，导进来的那一份直接落在里面。
- **组合**：题在左、答案在右摆好了，点顶上的「组合」→「存为组合」，文档库里多出一格，点它两栏一起摆回来，连翻到哪一页都记着。不想先摆出来就用「自由组合…」：左右各挑几份（同一本也能左右各放一份），拖着排好顺序，点「保存并打开」。它会换掉两栏里正开着的东西，所以按钮正上方先说清楚会换掉哪几本，被换掉的书页码都记着。拼到一半要退出，先问一声——它还没存在任何地方。
- **双文档工作区**：练习册与答案册同屏；分隔条可在 0:10 到 10:0 之间自由拖动，拖到底是**收起**该栏——队列一条不动，留下一个写着还剩几项的恢复按钮；左右可一键互换，互换保留各自的宽度与批注。
- **分栏**：两栏之间是一道 10px 的缝，四周、顶上那一排和两栏之间也都是 10px 一格。缝里不画线，缝本身就是分隔，中间那枚握柄（带 φ 的胶囊）说明它能拖。只有握柄接拖动（可按范围往两边各伸出 12px、上下各 22px），缝的其余部分和卡片边上照样写字。比例一路跟着手指，两端没有磁吸：想要多窄就有多窄，把某一侧关掉需要把分隔条推到工作区边缘。拖动过程中两侧页面按松手后的真实缩放实时显示，因此左右两边的动画是同一个动作，松手也不再跳一下；双击分隔条回到 50:50 的过渡同样逐帧跟随。
- **放大缩小不卡**：PDF 的光栅化在**独立线程**里做（`pdf-render-worker.js` + OffscreenCanvas），并且留住最近几页不释放。前者让栅格化不再占住主线程，后者让同一页换个缩放不必把那一页的图重解一遍。真机上同一页连渲六个缩放级别：原来每次 488–544ms、帧间隔最坏 97ms；现在首次 602ms、之后 1–3ms、最坏 10ms。位图用 `bitmaprenderer` 零拷贝上屏，1961×2772 只要 0.1ms。
  pdf.js 官方不支持在 worker 里渲染，但它只在两处碰 `document`（判 `useWorkerFetch` 要 `baseURI`、FontLoader 要 `fonts`），worker 里这两样都拿得出真东西。桩只给这两个字段：以后升级若多碰了别的，会直接抛，客户端整条回退到主线程——功能一点不少，只是会卡，并留一行日志。
- **手写批注**：钢笔 / 铅笔 / 马克笔 / 荧光笔 / 橡皮，压感、颜色、粗细、不透明度可调；批注按页存储，与 PDF 内容严格分层，永不修改原文件。
- **铅笔画的是石墨**：石墨是被刮到纸的纹理上去的粉末，凸起处着色、凹陷处根本没碰到，所以一道铅笔线不是均匀的一条而是密密的一片颗粒。这做不到靠调制笔画宽度——那改的是轮廓，而特征在里面。实现是拿一张固定种子的噪点贴图当橡皮，从实心笔画上抠掉一部分，抠出的孔就是纸没吃到石墨的地方。贴图只生成一次（否则一平移一缩放，笔迹上的颗粒就重新洗牌，整篇字会在纸上爬），并且随页面而非屏幕缩放（颗粒属于纸）。
- **套索**：圈选批注后可整体移动、缩放、旋转；旋转与缩放共用选区中心，一个手势即可同时完成。整段手势只占一步撤销。圈完之后线旁浮出一条：复制、剪切、换颜色、删除；剪下来的能粘到另一页、另一栏，或者草稿纸上。
  复制出来的那一份就在同一张纸上，按住它可以直接拖到另一栏去。手指出了这块画布之后事件
  还在来（指针捕获），所以整件事从头到尾都在源那一侧，松手才问对面接不接得住。**越过分
  隔条的那一截会当场在对面画出来**——判的是这一片的外框和对面画布相不相交，不是手指在
  哪，因为一片大的选区，手指还在这边的时候它的右半边可能已经越过去了，而人要看的正是越
  过去的那半边。落下去按**屏幕上的大小**来：两栏缩放常常不同，照搬文档坐标会让它在松手
  那一刻涨一圈或缩一圈，前面一路铺垫的「慢慢挪过去」就毁在最后那一下。在源那一栏撤销是
  「就当没拖过」：这边回到按下去之前的位置，那边那一份跟着消失——少了后半句，一次撤销
  反而把内容变成了两份。
- **工具栏停哪儿**：按住把手，浮动工具栏能拖到左右两边或底边展开，丢进下面两个角收成一颗小球（拖近角落时球会胀大，像被磁铁吸着）。往上拖，靠近顶上就被顶上那一排接住——上面那两个角因此不再停球——收成一颗和那一排一样高的球，停在两个标签左右空当里松手的那个位置。点那颗球，整条横躺进这一排，从球那儿往两边长，碰上「练习 / 设置」才推着它走，一个像素都不多推；收着的球也推，推到头、手指再越过标签正中，球就翻到另一侧。在 ⋯ 里打开「自动收起」，一落笔它就自己收回那颗球。
- **划着挑**：点照旧是点。按住一支笔顺着工具栏划过去，手指底下浮起一滴玻璃，把底下那一格放大一点三倍，松手就换成手指底下那一支；颜色那一排也一样，划到横杠外面 44px 以外再松手算反悔。那滴玻璃挂在 `body` 上、浮在工具栏外面——工具栏自己带 `backdrop-filter`，里面再放一块会折射的东西，它看得见的「背后」只剩工具栏那层半透明的底，弯出来的图标和原来的叠成两个。液态玻璃里它是一滴凸透镜：库里那张贴图的位移是负的，等于一块凹透镜，压在图标上反而把它缩小、挤到一边。毛玻璃里只弯边上一圈；纸里是一枚钢笔水的圆，不折射。
- **自动对题**：按页列出题号与匹配到的答案位置，并标注可靠度；两本书未被确认配套时只提示“请核对”，绝不冒充确定答案。答案册按**关联**查找，不是“另一侧碰巧开着的那本”——关联绑在习题册上，与左右无关；答案册被压在草稿纸下面照样能查，索引与前台渲染是分开的，查一次不动任何一栏正在显示的东西。
- **保存批注**：批注默认 400ms 自动保存，工具栏另有显式的「保存」按钮——有未写入的修改时才可点击，因此灰掉本身就是“已保存”的状态。
- **导出 PDF**：本栏或书架上的 ⋯ →「导出 PDF」，存进「文档/对页」，重名自动加「(2)」。书的原文件一个对象都不丢，有笔迹的页在原内容后面**加画**一层矢量笔迹——字还能选、能搜，放大多少倍都清楚；笔迹落点按 pdf.js 自己的视口反算，转过 90/180/270°、带裁切框的页都对得上。加了密的书 pdf-lib 改不了，退成逐页画成图再拼，导完会说字不能选。笔记本每页 A4、连纸样一起，没写的页也在；草稿纸导成一页，大小按笔迹的范围来。
  整件事在 worker 里做，不卡界面；大文件分块过桥，原生那边先写一个隐藏的临时文件，写完才改成真名字，中途失败不留半截。写文件要「所有文件访问权限」（就是导入列本机 PDF 用的那个）：没给就先问，去设置里开了、回来，导出接着走；不给也只是导不了，别的照常。
- **手写优先的输入**：触控笔只用于书写，手指与鼠标用于平移与翻页。一根手指的含义由页面自己决定：捏放大到超出面板时滑动查看，页面本来就装得下时翻页——按手势起始的方向判定一次，中途不会改变，滑到页面边缘之后的下一次轻扫才翻页。
- **翻页是折纸**：往后翻固定左边，往前翻固定右边，纸按折痕对折过去，纸背是白的。被拉着的那一点永远在「折痕不越过固定边」的范围里（`page-fold.js` 的 `constrainFold`），斜着拉一个角也只动那一片；纸从判定成翻页的那一点才开始跟手，不会一拿起来就已经折过去四分之一。松手看最后 90ms 的速度：甩得够快就按甩的方向走（往回甩，折过一大半也退回），不快才看折过去多少（32%）；剩下那段是接着手速走的临界阻尼弹簧，每一帧照样守着固定边。中途试过一版绕装订边立起来的 3D 翻转，帧率更好，但太僵，拆了。
- **顶上那一排**：左边往桌上摆东西（导入、文档库、组合、新建纸张），正中「练习 / 设置」两个标签，右边「全部关闭」——一下清空两栏，每一本读到哪页都记着，书都还在文档库里。放不下时（竖着拿、分屏）先收字、只留图标，按真实宽度量，不猜断点。原来底边还有一枚放「练习 / 设置」的胶囊，连同收起它的手势、叫回它的把手一起拆了：**底边整条都是纸**，笔写到哪儿都是写字。
- **收起顶上那一排**：往上推就收起，两个标签跟着走，两栏顶上去。按在按钮和标签上也能推：过了 10px 定方向，竖着的归收起（那一下点击被吞掉，不会顺手换页），横着的归按钮自己。收起那一段只动 transform，两栏只在松手定了的那一刻排一次版，平板上逐帧量是 8–9ms 一帧。
  收起之后屏幕顶上不盖任何东西，叫回靠手势来分：栏头上的按钮照常点得到；从栏头上竖着往下拉过 10px，那一排跟手下来（那一下点击同样被吞掉）；从两栏上方的空白处往下拉也行。切换条、书页、草稿纸上往下划都不算。原来顶上盖着一条透明条专门接「往下拉」，可两栏顶上去之后整个栏头都在它底下，点什么都落在它身上。
- **三套主题**：设置 → 皮肤里是**液态玻璃**、**毛玻璃**、**纸**。
  **液态玻璃**照 [rdev/liquid-glass-react](https://github.com/rdev/liquid-glass-react) 的做法重写成原生 DOM（这个应用没有 React）：玻璃身子完全透明，背后的东西只在边上被一张位移贴图弯过去，中间透出来的是原样；外加两道跟着指针转的边光，按钮还有库里那点弹性。和库里不一样的几处都是实测出来的：身子上不能有任何底色（Chromium 给有底色的那一层套滤镜时，不再把磨过的背后算进去，整块发灰）；影子单独一层、画在身子后面（不然玻璃弯背后时会把自己的影子吸进来）；色散（红绿蓝各弯一次）在平板上每隔一帧要 50–67ms，所以只在静止时用——手一碰屏幕就换成只弯一次的那版，停下半秒再换回来，而静止时屏幕不重画，色散一帧都不用算。
  **毛玻璃**是改版之前那一套：白色半透的磨砂胶囊、平平的淡蓝、按下去的水波纹。两套玻璃是同一份尺寸，液态玻璃只在 `html` 上多挂一个 `data-glass`，来回换一个像素都不挪。
  **纸**不是把玻璃的灯关掉，而是另一种材质：玻璃靠透光与折射分层，纸靠明度差与一条切边——桌面比纸暗一档（白页才落得下去），切边是墨色的低透明度而非灰（这块屏幕上其余一切都是墨，中性灰会读成印刷线），影子只给真正悬空的东西。纸只在 `paper.css` 里换颜色、底、边、影子、圆角和磨砂，测试钉着它不许有一条改尺寸的声明，所以换到纸也一个像素都不挪（平板上逐帧量过，练习页四十个元素一个没动）。
- **不能把可读性押在模糊上**：凡是浮在文档上、又要被阅读的表面，都得自己不透明。这条最初是被一次误诊逼出来的——`backdrop-filter` 在真机上计算为 `none`，而 `CSS.supports` 报告支持，于是被记成了 WebView 的毛病。真正的原因是 CSS 压缩器：样式表里每条玻璃规则都手写了 `-webkit-` 前缀，lightningcss 把两种写法当成同一个属性、按「后写的赢」去重，产物里只剩前缀版，而这台 WebView 恰好只认无前缀那个。去掉手写前缀交给它自己生成之后，25 处玻璃全部生效。
  结论反倒留下了：当时横贯全屏的顶栏与底栏因此**故意**不磨砂——它们后面是正在读的那几行字。现在底栏拆了，顶上那一排收成几枚胶囊，浮在桌面上、和两栏之间隔着一道缝，本来就不压在字上。
- **为平板而调**：页面本身禁止缩放（捏合只归 PDF 面板，避免两级缩放争抢同一手势）；手掌搭在屏幕上不会选中文字或弹出长按菜单；越界拖动不会带动整个应用。
- **按压回弹**：胶囊控件按下即压缩，松开时按真实阻尼弹簧（response 0.34s、阻尼比 0.52，采样为 CSS `linear()`）回弹后落定。
- **不打扰**：版本更新改为**默认关闭**。检查更新原先在每次启动后自行运行，并把整屏更新日志盖在当时屏幕上的任何东西之上——包括刚导入文件时那个「这份文件是？」的提问框，于是那个问题就没法回答了。设置里的「自动检查更新」仍可打开，旁边的「检查更新」按一次查一次。
- **无障碍**：支持降低透明度、提高对比度、减少动态效果——以上动效在“减少动态效果”下全部退化为无位移。

## 技术栈

| 层 | 技术 |
|---|---|
| Web UI | Vite 8（打包用 Rolldown）、Capacitor 8 |
| PDF | pdfjs-dist（本地 vendored）；渲染与文本抽取在 worker 里（`src/pdf/pdf-render-worker.js`），主线程只做零拷贝上屏 |
| 批注 | 自研矢量墨迹层（`src/ink/`），IndexedDB 持久化 |
| 导出 | pdf-lib，在 worker 里做（`src/export/`）；原生那边由 `PdfFilesPlugin.java` 先写隐藏的临时文件、写完再改名 |
| 队列 | `src/pdf/deck-state.js` — 纯函数，一栏一个有序队列加一个当前项 |
| 草稿纸 | `src/scratch/` — 世界坐标相机、按可见区域绘制的底纹、复用同一个墨迹层 |
| 笔记本 | `src/note/` — 一份合成文档，页面按草稿纸的纸样现画（`note-document.js`），走 PDF 那一整套阅读器 |
| 文件夹与组合 | `src/pdf/folder-state.js`（纯函数）＋ `folder-store.js`；自由组合那张单子是 `combo-builder.js` |
| 对题 | 上述匹配引擎，纯 JavaScript，无依赖 |
| 本机文件 | `android/…/files/PdfFilesPlugin.java` — 查 MediaStore 列出全机 PDF，导出也经它写进「文档/对页」；网页那侧是 `src/pdf/pdf-files.js` + `pdf-picker.js` |
| 界面与主题 | `src/styles/liquid.css` 管尺寸与版式，三套主题共用；`paper.css` 只换材质；液态玻璃是 `src/ui/liquid-glass-react.js` ＋ `liquid-glass-react.css`（SVG 位移滤镜） |
| Agent 回答 | markdown-it ＋ KaTeX ＋ DOMPurify（`src/agent/answer-renderer.js`） |
| 本地存储 | IndexedDB（PDF 字节、笔迹、草稿纸、笔记本）＋ localStorage（会话、阅读位置、配套关联、文件夹、组合） |
| 离线 | Service Worker（`public/sw.js`） |
| 多语言 | 自研扁平词表（`src/core/i18n.js`），简体 / 繁体 / English |

多语言：设定页、浮动笔迹栏和后来加的界面（顶上那一排、文件夹、组合、导出、空桌面、使用手册）都走词表，三个语言文件现在各 512 条。「练习」这一屏还有一部分是硬编码的中文，接线没做完——答案面板、匹配理由、Agent 面板都在其中。日文与韩文撤掉了，i18n 那一层没动：把词表放回 `src/core/lang/`、在 `LANGUAGES` 里加一行就回来。

有一类中文明确不会翻译：`question-id`、`body-structure`、`outline-classify`、`pair-verifier`、`toc-filter`、`glyph-map` 六个文件里的中文是正则——「例题|习题|第X题」「答案|解答|证明」「目录|索引」——它们是引擎用来解析中文教材的模式，不是显示给人看的文字。翻译掉它们，题号识别与配套判定会当场失效。

预缓存的只有 6 项：首页、manifest、图标、pdf.js 及其 worker、KaTeX 的样式表。刻意不在其中的有两类：一是 Vite 产出的应用包，文件名带内容哈希、每次构建都变，本来就没法静态列出（fetch 走网络优先，顺手写进缓存——对一个应用包来说这也是更正确的策略，陈旧的包比慢的包更糟）；二是 168 个字符映射表、16 个标准 PDF 字体和 20 个 KaTeX 字形共 204 个文件，只有文档真的用到时才取，预缓存它们等于把首次启动花在多数人永远不会打开的文件上。

这张表出过一次真实故障：它曾经有 17 项，其中 13 项指向已经随识别栈删掉的文件（ONNX 运行时、公式识别模型）。每一项都被单独 catch 并警告，所以没有报错，只是每次安装打印十三条警告然后缓存了四个文件——而没有人读安装日志。现在 `test_ui_interactions.js` 盯着它：表里每一项都必须在源码树里真的存在。

`/vendor/` 下的东西是缓存优先的：它们是钉在仓库里的第三方构建，在同一个应用版本内不会变，缓存里的副本永远是对的答案。

## 原生层与 Agent 的现状

仓库里有 `src/agent/`、`src/native/`、`native/agent-proxy/` 和 `android/app/src/main/cpp/`，看起来像两套已经接好的东西。**它们都还没有工作，而且是两套互不相通的机制**——先说清楚，免得往错的那一套上加代码。

**① 进程内的 JNI 桥**（`libduiye_proxy.so`，随 APK 走）。三个位置：`agent`、`ocr`、`match`，都还空着——问它，它诚实地回 `UNIMPLEMENTED`。开机会探测一次并写进日志（设定 → 开发者选项 → 查看日志），所以「这一层还活着吗」在真机上看得见，不用连调试器。

`match` 那一位和另外两位不一样：答案匹配**现在就有实现**，在 JS 那边。那个位置是留给以后把计算搬到 C++ 的，JS 这一侧的口子已经开好（`preparePair({ matcher })`，契约在 `src/pdf/native-matcher.js`）。**闸门不经过那一层**——角色判定、配对身份、OCR 上限、区域选择都留在 `matching-engine.js`，而且它会对交回来的每一条结论再钳一次。换句话说：交出去的是计算，不是判断。

**② 本机 HTTP 代理**（`agent-client.js` → `127.0.0.1:8787` → `native/agent-proxy/`）。Agent 面板走的是这一条。但那个 C++ 程序**没有被打进 APK**——Android 的 CMake 只编 JNI 那两个源文件，`native/agent-proxy/` 是另一个 CMake 工程，没有构建步骤打包它、也没有代码启动它。所以平板上那个端口没人在听，Agent 面板按下去总是「无法连接本地 Agent 代理」。它是开发期的原型：在电脑上跑起来，再 `adb reverse tcp:8787 tcp:8787` 转过去。

面板本身在 v1.6.0 里长了几样：对着当前这一页可以自己提问；同一本书同一页的来回记成一段对话，换一页就是另一段（只在内存里，每段只留最近 6 轮）；回答按 Markdown 排版、公式用 KaTeX 渲染，不许出现链接和图片，渲染前后各过一遍 DOMPurify。代理那头接的是 OpenAI 兼容的 `/chat/completions`：只认 HTTPS，密钥只从环境变量读，页面文字和回答都不落日志；另有一个不联网的 mock 模式。用法见 [native/agent-proxy/README.md](native/agent-proxy/README.md)。

要接 OCR，走 ①。

## 开发与测试

```bash
npm install
npm run dev
npm run build
npm test              # 55 个测试文件，一条命令，全绿或者不绿
```

开 PR 和推 main 时，CI（`.github/workflows/security-scan.yml`）在英文、LF 换行的 Linux 上跑同一条 `npm test`，和中文 Windows 上不一样：断言中文文案的测试要先 `setLang('zh-CN')`，拿源码文件做断言的先把 `\r\n` 换成 `\n`。这两条都是在 CI 上挂过一次才补的。

另有两个检查，都是一次真实故障留下来的：

```bash
npm run check:licenses   # 会进 APK 的依赖，许可证是否与 MIT 相容
npm run check:upstream   # 还有多少行逐字来自上游，按可改写程度分档
```

`check:licenses` 挡的是 copyleft 依赖：混进来一个，整份作品就得跟着它走，而 `LICENSE` 写的是 MIT。这种错误不会让构建失败、不会让测试变红、装出来的包跑得好好的——只有专门去查才看得见。

`check:upstream` 需要一个指向上游的远端；没有就先加，push 地址故意设成无效值防手滑：

```bash
git remote add upstream https://github.com/strangelion/LaTeXSnipper_mobile.git
git remote set-url --push upstream no-push-to-upstream
git fetch upstream
```

真实教材语料（`corpus/`）属于受版权保护的教材文本，**不随仓库分发**；缺少语料时相关测试会自动跳过，`npm test` 仍然通过。若要跑全量回归，将语料放在 `corpus/data.json`，或用 `FIND_ENGINE_CORPUS` 指向它。

Android 构建需要 JDK 21、Android SDK 36。全新 clone 即可直接构建，无需子模块、
无需手工放置任何二进制依赖：

```bash
npm run build:android
cd android && ./gradlew assembleDebug
```

Gradle 工程曾引用两项仓库里没有的依赖（`llama.cpp` 子模块与
`onnxruntime-genai-android-0.6.0.aar`），因此旧版本的全新 clone 无法构建。二者
都属于已经移除的识别（OCR）功能栈，Web 端并不使用，现已连同 `app/ocr` 下的
Java 实现一并删除。
